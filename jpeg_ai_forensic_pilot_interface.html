What this interface implements

This tool is the interactive counterpart to the pilot feasibility study (Section 5) of “Forensic Integrity and Tamper Localization in JPEG AI-Compressed Images.” It covers only the legitimate encode/decode path and the Class B (pixel-domain) threat branch of the full framework (Fig. 1). Implemented legitimate path, Class B tamper, Dpix baseline, all Section 5 metrics.   Not implemented Class C latent-domain tampering and the latent-aware detector Dlat, because both require access to the actual JPEG AI encoder/decoder internals (ga, gs, the hyperprior entropy model), which cannot run inside a browser page. A future version could add these once a WebAssembly build of the JPEG AI reference software exists.

Why a proxy codec?

Exactly as in the paper's pilot study, this interface substitutes the browser's built-in, standards-based JPEG encoder (canvas.toDataURL('image/jpeg', q)) for the JPEG AI analysis/synthesis transforms ga, gs of Eq. (1)–(2). All reported PSNR, F1 and IoU numbers are therefore conventional-codec proxy numbers, not JPEG AI performance figures — they demonstrate that the evaluation pipeline (Algorithms 1–3) runs correctly and reproducibly, exactly as intended in Section 5 of the paper.

Equations used

PSNR(x,x̂) = 10·log₁₀(255² / MSE)

Δ(i,j) = |x̂(i,j) − Dec(Enc(x̂; q'))(i,j)|, M̂ = 𝟙[Δ ≥ τ]

F1 = 2·Precision·Recall / (Precision+Recall), IoU = |M̂∩M| / |M̂∪M|

Limitations

  • Results depend on the browser's own JPEG encoder implementation and are not bit-exact reproducible across browsers.
  • Only rectangular copy-splice tamper is simulated (Algorithm 1, Class B); inpainting/generative edits are out of scope here.
  • The ELA baseline is intentionally the simple, closed-form detector of Eq. (6) — it is expected to perform modestly (see the paper's Table 2), motivating the learned detectors proposed in Section 4.5.
